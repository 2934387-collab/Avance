# Avance — учёт авансов и операций

## Что это за проект

`avance` — небольшой статический веб-сервис для создания документов учёта авансов. В нём можно:

- войти или зарегистрировать пользователя;
- создать документ с датой, номером, организацией, именем и начальным остатком;
- добавлять расходы и доходы;
- автоматически рассчитывать итоговый баланс с учётом начального остатка;
- сохранять документы в Supabase;
- открывать, удалять и печатать сохранённые документы;
- выбирать организацию и имя из ранее использованных значений;
- формировать сводный отчёт за период с разбивкой по организациям и документам;
- открывать сохранённые документы в новой вкладке и видеть их финансовые итоги в списке.
- просматривать список сохранённых документов на отдельной странице-режиме с возвратом к редактору.
- при изменении сохранённого документа подтверждать полный пересчёт остатков и пересчитывать цепочку документов по организации и имени.

Проект рассчитан на личное использование и не содержит отдельного backend-сервера: браузер обращается к Supabase напрямую через JavaScript-клиент.

## Где хранится

Проект находится в рабочей папке AgentGoga:

```text
C:\Users\Local\AgentCodex(ChatGPT)\agentGoga\avance
```

Основная страница запускается из файла `index.html`.

## Используемые технологии

- HTML5 — структура страницы и формы;
- CSS3 — внешний вид, адаптивная мобильная версия и стили печати;
- JavaScript без фреймворков — логика приложения;
- Supabase — авторизация и хранение документов;
- PostgreSQL внутри Supabase — таблицы `documents` и `operations`;
- Supabase JS v2 — загружается из CDN `unpkg.com`.

Зависимости npm и сборщик не используются. Для базового запуска достаточно браузера и доступа к интернету.

## Как запустить локально

### Вариант 1: открыть файл напрямую

Открой `index.html` двойным щелчком. Для входа и работы с базой потребуется интернет.

### Вариант 2: запустить локальный HTTP-сервер

Из папки `avance` выполни одну из команд:

```powershell
py -m http.server 8000
```

Затем открой в браузере:

```text
http://localhost:8000
```

Локальный сервер обычно удобнее для проверки, потому что страница работает в обычном HTTP-контексте.

## Настройка Supabase

1. Создай или открой проект в [Supabase](https://supabase.com/).
2. Если проект находится на паузе, нажми `Resume project`.
3. Открой раздел `SQL Editor`.
4. Выполни содержимое `supabase_schema.sql`.
5. В настройках авторизации проверь разрешённые способы входа по email и пароль.
6. В `app.js` должны быть указаны актуальные адрес проекта Supabase и publishable key.
7. Обнови страницу после изменения настроек.

В текущей версии параметры Supabase находятся в первых строках `app.js`. Publishable key предназначен для клиентского приложения, но секретные service role keys, пароли и токены нельзя помещать в HTML, JavaScript или README.

## Структура данных

### `documents`

Хранит шапку документа:

- `id` — идентификатор документа;
- `user_id` — владелец документа;
- `document_number` — отображаемый номер;
- `number_value` — числовая часть номера для последовательной нумерации;
- `document_date` — дата документа;
- `organization` — организация;
- `person_name` — имя сотрудника или получателя;
- `opening_balance` — остаток на начало;
- `ending_balance` — остаток на конец;
- `created_at`, `updated_at` — даты создания и изменения.

### `operations`

Хранит строки документа:

- `operation_date` — дата операции;
- `name` — название или описание;
- `amount` — сумма;
- `operation_type` — `expense` для расхода или `income` для дохода;
- `document_id` — связь с документом;
- `user_id` — владелец операции.

Формула конечного остатка:

```text
остаток на конец = остаток на начало + доходы − расходы
```

## Безопасность данных

В базе включён Row Level Security (RLS). Политики разрешают пользователю работать только со своими документами и операциями. Связи с `auth.users` удаляют связанные данные при удалении пользователя.

Несмотря на RLS, перед публикацией нужно проверить политики в Supabase и не добавлять в клиентский код секретные ключи.

## Если появляется `Failed to fetch`

Обычно это означает, что браузер не смог обратиться к Supabase или загрузить библиотеку с CDN. Проверь:

1. проект Supabase не находится на паузе;
2. актуальны URL проекта и publishable key в `app.js`;
3. есть интернет-соединение;
4. `unpkg.com` не заблокирован сетью или расширением браузера;
5. в DevTools браузера во вкладке `Console` и `Network` нет ошибок DNS, CORS или блокировки запроса.

## Ограничения текущей версии

- нет отдельного backend-сервера;
- нет автоматического тестирования интерфейса;
- номер документа формируется в браузере на основе загруженных документов;
- библиотека Supabase загружается из внешнего CDN;
- для продолжительной работы бесплатный проект Supabase может потребовать периодического использования или перехода на платный тариф.
## Сводный отчёт

На главной странице доступна кнопка «Сводный отчёт за период». Отчёт фильтрует документы текущего пользователя по дате документа и имени, группирует результаты по организациям и показывает список операций, расходы, доходы, итоговый баланс и количество документов.

Итоговый баланс рассчитывается так:

```text
остаток на начало + доходы − расходы
```

Отчёт можно распечатать из браузера. Имена и организации сравниваются без учёта регистра и лишних пробелов; при вводе варианта существующего значения приложение предлагает использовать каноническое написание.
